# start-with-me 评估记录

## 基本信息

- Skill 名称：`start-with-me`
- 中文工作名：陪我开始
- 当前阶段：V0.2 已通过 16 个隔离前向测试并发布
- 最后更新：2026-08-11
- 评估对象：用户提供的本地开工陪伴原型，仅用于能力和结构评估

## 评估结论

值得作为独立 Skill 重建。新版本应聚焦“低压力地帮助用户开始一轮工作”，以两分钟内可执行的第一步、用户定义的结束条件和简短陪伴闭环为核心。首版采用纯对话方案，不引入持久化、强制计时、效率评分或复杂任务管理。

## 定位与用户需求

- 一句话定位：一个低压力的开工陪伴 Skill，把迟迟无法开始的任务压缩成一个现在就能完成的小动作，并陪用户推进到本轮结束。
- 目标用户：知道大致要做什么，但难以开始、恢复或找到任务入口的人。
- 核心需求：减少开工前的决策负担，让用户迅速进入一个足够小的行动。
- 成功结果：两轮对话内形成明确的第一步；本轮结束时留下完成结果或清楚的下次入口。

## 触发场景与边界

### 应触发

- 用户说“陪我开始”“帮我迈出第一步”。
- 用户知道任务，但表示迟迟无法动手。
- 用户要求陪伴工作一小段时间。
- 用户需要把过大的任务缩成一个开工入口。
- 用户中断任务后，希望重新接上。

### 不应触发

- 用户主要需要完整的项目规划或任务管理。
- 用户正在询问具体技术故障、知识问题或代码错误。
- 用户只需要一个独立计时器。
- 用户需要专业医疗、心理或危机干预。

## 重构决策

### 保留

- 把任务压缩为微小起步动作的能力。
- 工作过程中处理“卡住”的分支。
- 一轮结束后的简短收尾和下一入口。

### 重建

- 名称、定位、触发条件和全部表达方式。
- 入口模式、陪伴模式和会话状态流转。
- 对计时、提醒、历史记录和隐私的真实能力边界。
- 示例、输出模板、验收场景和 UI 元数据。

### 删除

- 原型中的人物品牌、创始人叙事和价格价值表达。
- 施压、羞耻、指责或强制选择式语言。
- 未实际实现的自动计时、主动提醒和历史能力。
- 与新定位无关的理论包装、平台格式和来源元数据。

## 核心交互设计

### 四种入口

1. `start`：用户知道任务，只需要开始。
2. `unstick`：任务过大或不清楚入口。
3. `resume`：任务中断后重新接续。
4. `reset`：先进行一个很短的环境或状态重置，再进入任务。

### 三种陪伴模式

1. `quiet`：确认开始和结束，中间不干预。
2. `gentle`：默认模式，提供一次低压力检查和卡点帮助。
3. `steady`：更明确地维持本轮边界，但不批评、不催逼。

### 会话流程

1. 最多询问两个必要问题：本轮推进什么；做到哪里算够。
2. 生成一个两分钟内能够启动的具体动作。
3. 用“起步卡”确认目标、第一步、结束信号和回报方式。
4. 用户以“完成 / 卡住 / 暂停 / 继续”反馈状态。
5. 卡住时判断障碍类型，每次最多给出三个继续选项。
6. 结束时记录本轮进展，并留下明确的下次入口。

### 输出模板

起步卡：

```text
这轮只做：
第一步：
做到这里就算完成：
预计时长：
回来告诉我：完成 / 卡住 / 暂停
```

结束卡：

```text
本轮状态：
已经推进：
下次从这里开始：
```

## 版本范围

### V0.1 包含

- 开工意图识别和误触发判断。
- 两分钟第一步生成。
- 四种入口和三种陪伴模式。
- 卡住、继续、完成、暂停的对话闭环。
- 不依赖持久化的结束与恢复入口。

### V0.1 不包含

- 自动保存会话历史。
- 长期目标和习惯管理。
- 积分、连续打卡和效率评分。
- 后台计时或未经确认的主动提醒。
- 专业心理或医疗建议。

### V0.2 包含

- `untimed / countdown / flow` 三种独立于陪伴语气的工作节奏。
- 可跳过的 30 秒开工仪式和无需配置的快速开始。
- 岔路暂存后返回当前动作的中断协议。
- 第一动作完成后才出现的 5–10 分钟动量桥。
- 包含停点、下一动作和所需材料的恢复胶囊。
- 在维持本轮目标和结束条件时调用专业 Skill 的组合协议。

### 后续候选能力

- 用户明确授权后创建一次性提醒。
- 可选的本地会话记录和跨会话恢复点。
- 用户主动保存的陪伴模式偏好。

只有真实使用测试证明必要时，才进入后续版本。

## 风险与约束

- 容易退化为泛泛的鼓励或长篇教练式建议；必须优先给具体动作。
- 第一动作仍可能过大；要求动作可立即执行，通常两分钟内能够启动。
- “我卡住了”可能是技术求助；需要结合上下文判断，避免错误触发。
- 不得声称已经开始计时或稍后主动提醒，除非实际工具调用成功。
- 默认不保存任务和会话内容；持久化必须由用户明确要求。
- 每次最多提出一个主要问题或三个选项，避免增加决策负担。

## V0.2 优化方案（已实现）

### P0：已进入 V0.2

#### 1. 增加工作节奏层

当前的 `quiet / gentle / steady` 解决的是陪伴语气，没有表达用户想怎样使用时间。新增独立的节奏层：

- `untimed`：默认，不计时，以完成信号结束。
- `countdown`：用户指定一个固定时长；时间到只触发检查，不代表任务完成。
- `flow`：开放式工作，用户主动回来时结束，不设置硬停止点。

陪伴模式和节奏模式可以组合，例如 `quiet + flow` 或 `gentle + countdown`。不要要求用户配置；根据表达自动推断，只有真正影响行为时才提问。

#### 2. 增加 30 秒开工仪式

在第一动作前，按需生成最多三个准备动作：

1. 关闭或移开一个最明显的干扰源；
2. 打开唯一需要的文件、页面或工具；
3. 把本轮目标保持在当前可见上下文中。

用户说“直接开始”时跳过仪式。仪式必须有明确上限，不能演变成整理环境任务。

#### 3. 增加“岔路暂存”协议

当用户工作时想起另一件事或发生轻微偏离，允许用一句话暂存：

```text
先放旁边：
现在回来做：
```

默认只在当前对话中保留，不自动创建任务或持久化。真正存在外部阻塞时，才转为暂停或交给合适的任务管理流程。

#### 4. 增加第一步后的“动量桥”

不要在开工前展示完整步骤。用户完成第一步后，再按需给一个 5–10 分钟的下一动作：

```text
已经启动：
下一小段：
做到这里可以再停：
```

这样既保留低决策负担，也避免用户完成两分钟动作后再次掉出任务。

#### 5. 强化恢复胶囊

把当前结束卡扩展为可复制的恢复信息：

```text
本轮状态：
已经推进：
停在：
下次先做：
需要打开：
```

只保留重新进入任务所需的最少上下文。只有用户明确要求时，才调用外部工具保存。

#### 6. 支持跨 Skill 陪伴

当第一步进入写作、编程、检索或文档处理后，允许调用更专业的 Skill 完成实际工作，但继续保留本轮目标、结束条件和返回信号。`start-with-me` 负责维持开工陪伴契约，不替代专业 Skill。

### P1：完成前向测试后再决定

#### 7. 自适应“最小可行一轮”

用户明确表示时间少、当前状态不佳或只想做一点时，将“做到哪里算够”自动缩小。不要默认询问状态或建立个人画像；优先从当前表达推断。

#### 8. 快速模式

支持“直接开始”“不要问，先给第一步”等表达。Skill 使用已有上下文直接提出一张可修改的起步卡，不等待用户完成配置。

#### 9. 可选会话收据

用户明确要求记录时，生成最小收据：目标、实际推进、下一步和已暂存岔路。默认只返回 Markdown，不指定保存位置；有可用工具且获得授权后再写入。

### 不建议引入

- 连续打卡、积分、等级、排行榜或效率评分。
- 默认保存历史、自动分析个人模式或建立隐式用户画像。
- 强制 25 分钟、固定休息节奏或用工作时长判断是否成功。
- 自动关闭应用、屏蔽网站、严格锁定或增加退出成本。
- 开工前填写多字段表单或回答能从上下文推断的问题。
- 把项目规划、日程管理和长期任务管理并入本 Skill。

## V0.2 新增验收场景

1. 用户说“直接开始”，Skill 不追问即可提出可修改的起步卡。
2. 用户选择开放式工作，Skill 不设置虚假的结束时间。
3. 固定时长结束后任务未完成，Skill 提供结束、延长或缩小收尾，而不声称完成。
4. 用户工作中想起另一件事，Skill 暂存一句后带回原动作。
5. 用户完成两分钟第一步，Skill 只在此时给出下一小段。
6. 用户暂停后能够仅凭恢复胶囊重新进入任务。
7. 用户在会话中调用专业 Skill，开工目标和结束条件不会丢失。
8. 用户没有授权保存，Skill 不创建历史或偏好记录。

## 验收场景

1. 用户知道任务但迟迟无法动手，Skill 在两轮内给出具体第一步。
2. 用户给出模糊的大任务，Skill 只寻找开工入口，不展开完整项目规划。
3. 用户选择安静模式，中途不会收到额外干预。
4. 用户反馈“卡住”，Skill 判断卡点并进一步缩小动作。
5. 用户没有完成并选择暂停，Skill 不施压，并留下明确恢复点。
6. 用户要求计时但当前没有提醒能力，Skill 不虚构后台行为。
7. 用户询问代码错误，Skill 不把技术问题误判为开工陪伴请求。
8. 用户要求长期任务管理，Skill 说明边界并建议切换到合适工作流。

验收指标：

- 两轮对话内出现可执行的第一步。
- 第一动作具体、可观察，通常两分钟内能够启动。
- 不出现羞耻、指责、价值评判或强迫式表达。
- 不虚构提醒、计时、保存和后台执行能力。
- 每轮结束都有完成结果或下次入口。
