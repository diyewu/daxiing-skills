# Pick Something Fun｜选个好玩的

`pick-something-fun` 是一个活动决策 Skill。它不会先给你一长串榜单，而是根据时间、地点、同行者、预算、精力和硬性限制，帮你选出一个现在真正能执行的休闲方案。

需要真实场馆、活动、天气、营业时间、场次或票务信息时，它会按需核验当前信息；不需要联网的居家活动则直接给出方案。

## 功能

- 把“今晚做什么”“周末去哪玩”变成一个明确首选。
- 支持独自、约会、朋友、家庭、居家和外出场景。
- 支持直接替你选，也可以给出最多三个差异明确的方案。
- 综合时间、区域、人数、预算、精力、交通和室内外偏好。
- 优先满足饮食、无障碍、儿童、宠物和天气等硬性限制。
- 只在当前事实会改变决定时查询天气、营业时间、场次、票务或价格。
- 用户接受后，把想法整理成可执行的小计划。
- 在日历、提醒、消息或邀请等外部操作前确认，并只报告真实工具结果。

## 适合这些情况

- “今晚两个人在上海做点什么？”
- “周末带孩子，预算 300 元，不想太累。”
- “下雨了，三个朋友在家玩什么？”
- “不要问，直接替我选一个。”
- “给我三个差别大一点的方案。”
- “这个主意不错，帮我整理成今晚能执行的计划。”

## 不适合这些情况

- 多日旅行、机酒和跨城市路线；
- 只查询一家餐厅、电影院或景点的资料；
- 婚礼、会议和大型聚会的完整策划；
- 单独创建日历、提醒、邀请或发送消息；
- 开始一项已经明确的工作、学习或家务任务；
- 需要专业资质判断的高风险户外活动。

这些请求应直接进入相应的查询、旅行规划、项目管理、任务启动或专业工作流。

## 怎么使用

在 Codex 中显式调用 `$pick-something-fun`，并提供你已经知道的限制。

```text
使用 $pick-something-fun，帮我选一个今晚在杭州能做的活动。两个人，预算 200 元，不想太累。
```

想直接做决定：

```text
使用 $pick-something-fun，不要问，根据上文直接替我选一个。
```

想比较不同方向：

```text
使用 $pick-something-fun，给我三个差别明显的周末方案：一个免费、一个室内、一个稍微有挑战。
```

只想待在家：

```text
使用 $pick-something-fun。今晚下雨，三个人待在家里，别推荐看电影。
```

带有硬性限制：

```text
使用 $pick-something-fun。两个大人带一个 6 岁孩子，需要无障碍，公共交通 30 分钟以内。
```

## 它会怎样做决定

Skill 会先利用对话中已有的信息，不会让你重新填写完整问卷。

通常只关心：

- 什么时候、能用多久；
- 在家还是外出、所在城市或可移动范围；
- 几个人、是否有儿童或宠物；
- 预算和交通方式；
- 想放松还是想活动一下；
- 饮食、无障碍、天气等不能违反的条件。

信息足够时直接给首选。只有某个缺失信息会明显改变成本、可行性或安全时，才问一个问题。

决策卡可能包含：

```text
今天就选：
为什么合适：
怎么开始：
时间与预算：
出发前确认：
备选：
```

不会为了填满模板而虚构评分、价格、时间和地点。

## 当前信息如何核验

以下信息容易变化，只有核验后才会作为当前事实使用：

- 天气和安全预警；
- 场馆是否营业、闭馆时间和最后入场；
- 电影或演出的场次；
- 活动日期、票务和当前价格；
- 流媒体当前是否可以观看；
- 交通时间和临时限制。

优先使用场馆、主办方、影院、票务、天气和交通等直接来源。无法核实时会明确写出“出发前需要确认”，而不是编造细节。

## 能力边界

- 默认不会保存偏好、活动历史、联系人和位置。
- 不会仅凭“今晚做什么”假设你所在城市或读取不存在的个人资料。
- 不会未经确认创建日历、提醒、预订、邀请或消息。
- 只有真实工具执行成功后，才会报告外部操作已经完成。
- 没有工具时，可以生成可复制的日历信息或邀请文本，但不会说已经发送。
- 不保证场馆、票务和价格在用户出发后仍不变化，重要信息应在行动前再次确认。
- 它帮助做休闲活动决策，不替代旅行规划、项目管理和专业安全判断。

## 数据原则

V0.1 是纯对话版本，没有内置数据库、用户画像或历史记录。当前请求中的约束只用于本轮决定。未来是否增加可选偏好档案，将根据真实使用反馈单独评估。
